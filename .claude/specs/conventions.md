# spmMathTools — Conventions & Patterns

## File & Directory Naming

- Operator extensions: `Type+OperatorCategory.swift` (e.g. `Quaternion+Arithmetic.swift`)
- Functional extensions: `Type-FunctionName.swift` (e.g. `Waveform1D-Calc.swift`)
- Constructors: `Type+ConstructorName.swift` in a `Constructors/` directory
- Support types: one-type-per-file under `Support/`
- Enums: one-enum-per-file under `enums/`

## Code Style

- MARK comments for sections (`// MARK: - Properties`, `// MARK: - Methods`)
- `@inline(__always)` on hot-path helpers (OTG, root solvers)
- Operator overloads separated by category (Arithmetic, Compound, Unary, Comparison, Bitwise, Custom)
- Generics constrained to `BinaryFloatingPoint & SIMDScalar` for Spatial types; `Numeric & Sendable` for Waveform1D
- Prefer `Double` precision; `Float` overloads provided for GPU/SIMD interop

## OTG Module

- Port of the **Ruckig** C++ library (jerk-limited trajectory generation)
- Reference paper in `docs/Ruckig/`
- Python debug harness in `debugSupport/`
- Performance target: C++ averages ~2.4 µs; current Swift averages ~73.6 µs (30x gap)
- Truth tables generated by `debugSupport/generateRandomTrajectories.py`
- Core types (Profile, Block, Trajectory, BrakeProfile) are **value types (structs)**; no `copy()` required

## Polynomial Module

- Coefficients stored highest-degree-first: `[aₙ, aₙ₋₁, …, a₁, a₀]`
- Evaluation via Horner's method
- Class hierarchy: `PolynomialUnivariateFunction` base → `ZeroUnivariatePolynomial`, `ConstantUnivariateFunction`, `LinearUnivariateFunction`, …, `DecicUnivariatePolynomial`
- Root solvers: closed-form up to quartic; quintic+ throws `MathErrors.rootsUnsolveableFor`
